The shape of a static blog

            
Toby Davis · 2026-05-04 · 8 min read


            
By default, the page shows just the article — title and content. The table of contents is hidden above the viewport.


            
Scroll down a few hundred pixels, then start scrolling back up. The ToC slides into view from the top, like a smart navbar reappearing. Reverse direction again and it slides back out. The burger button at the top-left stays visible once you've scrolled, giving an alternative way to summon the full ToC as a popover.


            
Introduction

            
This is the smart-navigation pattern most modern apps use: hide secondary chrome by default, reveal it on intent. "Intent" is detected here as a scroll-up gesture — when the user reverses direction, they're usually looking for navigation.


            
The animation is direction-driven, not position-driven. A small JS scroll listener tracks delta between consecutive scroll positions and toggles a single class on the ToC element. CSS transitions handle the rest, animating only transform and opacity for compositor-friendly performance.


            
Building blocks

            
Pick a reveal style on the left. Slide is the cleanest, Drop adds a tiny spring, Fade is the most subtle, Blur-fade combines a small lift with the fade for a soft focus-pull feel.


            
Tune the reveal duration if you want it punchier or more leisurely. The hide threshold controls how much downward scroll is required before the ToC slides back out — set it higher if accidental scrolls feel jumpy.


            
Conclusion

            
This pattern keeps the page distraction-free at rest while making navigation a single gesture away. Apple, Google, and most modern reading apps use this exact mechanic.
